## Improvements

1. Split the tab-spawn row into the two actual paths. `prepareAgents` runs only for a new tab. An existing tab goes straight from `spawnPartition` to `growFleetIntoGroup`, which reaches `placeAgent` and opens the pane without a `PreparedAgent`. Resolve once per agent in the existing-tab orchestration, before placement, and pass `LaunchPolicy` to the placement helpers. Await `prepareAgents` on the new-tab path and pass its result through `launchPrepared`, including the root env when seating a new home. Don't strand the current worktree: resolve policy before creating it or put it on the cleanup list before any operation that can throw. I agree with both reviewers that preparation belongs before the pane opens; the new-tab fix does not cover existing tabs.
2. Finish the restart env contract at every caller. `terminal-relaunch.ts` has both `relaunchPlace` and `relaunchTerminal`, and `restartAttached` already gets `prepared.env` from the adapter's terminal attachment but currently passes only its command. Carry the fresh policy and attachment env through both helpers. For the held role, rebuild the same env as a fresh held spawn, including `ORCH_PROJECT`, launch credentials and the held environment stamp, rather than substituting `spawnEnv`, which does not supply all of these. Name `PtyHolder.relaunchPid` and its test fixture in the signature change. For pane fallback, use a shell-launch capability that can remove old policy keys and apply fresh ones, or explicitly refuse the restart before stopping the old process when that capability is absent. Leaving the old policy in effect on a supported restart still violates Bryan's second ruling, even if Claude does not take that path.
3. Make snapshot publication distinguish an existing snapshot from a failed write. I agree with Opus and Sonnet that install writes must always propagate failure. I disagree that `fs.existsSync(file)` makes the worker catch sound: the catch surrounds directory creation and temp writes too, and existence proves neither a rename failure nor a valid file. Restrict deduplication to a publish operation that reports the destination already exists, for example linking the complete same-directory temp file into the content-addressed name and accepting only its `EEXIST` in the adapter-owned directory. Keep atomic rename for mutable install config; propagate all other errors and clean up the temp file. Test concurrent publishers, an error before publish even when the destination exists, and a failed install rename.
4. Define the preview and shell boundaries without claiming equality that the design cannot guarantee. A preview omits `orchDir` and therefore the native settings argument; remove the claim that it is the exact launched command. Give a linked plan a distinct shape with no preview `cmd` and do not admit or expand its model against the origin catalogue before forwarding; the receiving host should admit it before preparing policy. I agree with both reviewers that shell quoting belongs at the shared shell boundary, not in Claude. To preserve the every-launch guarantee, include native argv rendering at that boundary, including the shell-command path used for restart, with a spaced `orchDir` test; leave raw argv consumers unquoted.
