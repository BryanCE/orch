## 1. `workers` settings
- `inherit_extensions`: boolean, default `true`; “Whether workers inherit harness extensions.” `packages/orch/src/settings/schema.ts:120,196-207`; `packages/orch/src/settings/registry.ts:193`.
- `inherit_mcp`: boolean, default `false`; “Whether workers load the user's MCP servers and connectors. Off, the default, launches them with none, so no MCP tool definition costs tokens. The next worker launch takes a change.” `schema.ts:120,196-207`; `registry.ts:194`.
- `exclude_extensions`: `ExtensionExclusions` map (harness to string list), no default; “Extensions workers must not load, by harness, each in that harness's naming: {"<harness>": ["<extension>"]}. An LSP plugin starts a language server per worker. The next worker launch takes a change.” `schema.ts:196-207`; `registry.ts:195`.
- `builtin_tools`: boolean, default `true`; “Whether workers receive built-in tools.” `schema.ts:120,196-207`; `registry.ts:196`.
- `allow_tools`: string array, no default; “Tools workers may use.” `schema.ts:196-207`; `registry.ts:197`.
- `verify_commands`: command string array, no default; “Commands a worker runs to verify its own slice, named in its header. Write {cwd} (or {wincwd} for a Windows tool such as powershell.exe) for the agent's own directory; a fixed path is refused.” `schema.ts:203-207`; `registry.ts:199`.
- `compact_at_tokens`: harness/model-to-positive-integer table, default `{}`; “The context size, in tokens, at which a worker compacts, per harness and concrete model (the full model id, never an alias). An alias launch takes the point of the model it runs now. A model with no entry keeps the harness's own default. Only a harness that takes a compaction point is offered.” `schema.ts:120,207`; `registry.ts:198`.

## 2. Worker tool and extension policy at launch
- **pi:** `workerPolicyFrom` resolves `workers` once. `piToolArgv` adds `--no-builtin-tools` when configured and `--tools <allowlist>`; `piExtensionArgv` adds `--no-extensions -e <orch bridge>` then explicitly adds each inherited, non-excluded user extension using `-e <file>`. These are argv, in interactive and headless restricted launch. `packages/orch/src/policy/workers.ts:18-31`; `packages/orch/src/adapters/pi.ts:78-98,117-130,339-344,449-466,487-495`.
- **omp:** same `WorkerPolicy` mapping; `--no-tools` turns off built-ins, `--tools` supplies an allowlist, and `--no-extensions -e <orch bridge>` plus `-e <file>` supplies inherited, non-excluded extensions. argv for both restricted launch forms. `policy/workers.ts:18-31`; `packages/orch/src/adapters/omp.ts:53-64,96-113`.
- **claude:** exclusions become `enabledPlugins: {plugin: false}` in orch's worker settings file; no `workers.tools` allowlist is applied (no `WorkerLaunchRole`). When MCP inheritance is off, argv adds `--strict-mcp-config`; when on, it omits that flag. `inherit_mcp` also controls `ENABLE_CLAUDEAI_MCP_SERVERS` in settings. `packages/orch/src/adapters/claude.ts:77-89,142-145,232,239-240`.
- **codex:** no `WorkerLaunchRole`; neither tools nor excluded extensions are mapped into a worker launch. `packages/orch/src/adapters/codex.ts:105`.
- **opencode:** no `WorkerLaunchRole`; neither tools nor excluded extensions are mapped into a worker launch. `packages/orch/src/adapters/opencode.ts:51`.

## 4. Worker prompt clauses and inclusion conditions
- Always: `[orch worker] No human watches you. Verify the files you edited before you report; a task that edits no file runs no verify command. Every orch verb (spawn, dispatch, steer, close, reset, status) stays forbidden. Do the work yourself. A slice too big for one agent is reported back, not split by you.` `packages/orch/src/worker-prompt.ts:18-22`.
- Verification instruction: if `verify_commands` is empty, “Run the tests and typechecks this repository already has”; otherwise list configured commands, replacing `{cwd}`/`{wincwd}` when cwd is available, and append the working-directory instruction if present. `workerRules` supplies gated commands and verify commands from settings. `worker-prompt.ts:14-16,31-35`.
- Worktree clause: included only when `worktreeBranch` exists; says the worker runs in its own git worktree and must commit before reporting. `worker-prompt.ts:47-50`.
- Spawn clause: `maySpawn === true` yields “You may `orch spawn`; your children may not.” Otherwise “Never spawn subagents.” Context derives this from `maySpawnBelow(self, fleet.max_depth)`. `worker-prompt.ts:53-56`; `packages/orch/src/policy/spawner.ts:17-24`.
- Ask clause: if `adapter?.bridge?.takes.includes("answer")`, the header offers blocking `orch_ask`; otherwise, if the adapter echoes prompts, it instructs the worker to end its turn with the question so the answer arrives in its next prompt; otherwise omitted. `worker-prompt.ts:60-67`.
- Spawner clause: if the adapter has a bridge and `spawnerRepliable` is true, instructs final report as last reply and limits `orch_send target "spawner"` to question/blocker/finding; if spawner is repliable but adapter has no bridge, this clause is omitted. If not repliable, the no-spawner clause says finish and let orch collect the final reply, never relay through another agent. `worker-prompt.ts:69-87,98-106`.
- Gated-command clause: included only if `gatedCommands.length > 0`; lists commands requiring human approval and instructs reporting request id and retrying exact command only after approval. `worker-prompt.ts:90-94,106`.
- `workerPrompt` bypasses the entire header when `raw` is true. `worker-prompt.ts:156-157`.

## 5. `dispatch` request `worker` field
- It optionally supplies `{ harness: AdapterId | null, context: WorkerHeaderContext }`; the daemon resolves that adapter and wraps text in `workerPrompt(..., false, adapter, context)`. Absent `worker`, it calls `writeText` with the original text, so yes, dispatch can reach an agent with no worker header. `packages/orch/src/daemon/client/protocol.ts:633-634`; `packages/orch/src/daemon/server/handlers/write.ts:324-330`.
- The `WorkerHeaderContext` fields are `maySpawn`, optional `cwd`, optional `worktreeBranch`, optional `verifyCommands`, optional `gatedCommands`, optional `spawnerRepliable`. `packages/orch/src/types/core.ts:200-216`.

## 6. Command restrictions and enforcement
- `denied_commands`: object `{commands: CommandPattern[], applies_to: Role[]}`; default `{applies_to: ROLES.filter(role !== "orch")}` = slave workers only; configured command default is absent/empty. Enforced through the command-gate matching and daemon `command-lock` verdict, then `cmdLock` refuses a denied verdict with “no agent of your kind may run it.” `packages/orch/src/settings/schema.ts:105-106,123,302-305`; `packages/orch/src/settings/registry.ts:244-245`; `packages/orch/src/policy/command-gate.ts:56-57`; `packages/orch/src/commands/lock.ts:23-28`.
- `gated_commands`: `CommandPattern[]`; default `ssh`, `ssh.exe`, `scp`, `sftp`, `rsync`; no role selection (the human's own shell is not gated). Enforced by `command-gate.ts` pattern matching and the `command-lock` handler/`cmdLock`; refusal asks the human to grant the request. `schema.ts:109,301`; `registry.ts:243`; `command-gate.ts:56-57`; `commands/lock.ts:21-25`.
- `locked_commands`: object `{commands: CommandPattern[], applies_to: Role[]}`; default `{applies_to: ROLES}` = `orch` and `slave`; command list absent/empty by default. Enforced by `gatedPatterns`/`lockedCommandLine` to route harness commands through `orch lock`, and daemon `command-lock` arbitration (waits for lock). `schema.ts:105,121,297-300`; `registry.ts:241-242`; `command-gate.ts:56-69`; `commands/lock.ts:14-36`.
- Roles are exactly `"orch" | "slave"`. `packages/orch/src/types/policy.ts:65-67`.

## 7. Per-spawn or per-agent configuration
- These limits are install-wide settings, not per-spawn or per-agent: `OrchSettings.workers`, `denied_commands`, `gated_commands`, and `locked_commands` carry settings values. Launch `WorkerPolicy` is passed in spawn options and has tools/extensions policy but no denied/gated/locked command fields; `SpawnOpts` has `tools` and `workers` but no command-rule overrides. `packages/orch/src/types/settings.ts:55`; `packages/orch/src/types/adapter.ts:20-42`; `packages/orch/src/types/policy.ts:79-96`; `packages/orch/src/daemon/client/protocol.ts:679-685`.
